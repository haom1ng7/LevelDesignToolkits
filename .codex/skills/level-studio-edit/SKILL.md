# 维护关卡设计工具箱功能

从用户描述中确定触发方式与期望结果，并在本项目实现可验证的变化。项目根目录有 `package.json` 和 `.codex/README.md`；不要把技能目录当作命令工作目录。

## 定位与实现

1. 阅读 [项目上下文](../../project-context.md)、[源码规则](../../rules/development.md) 和 [编辑器行为规则](../../rules/editor-behavior.md)，只追踪本次涉及的模块。
2. 先沿现有入口追踪状态、几何、场景与事件的调用关系。模型和渲染对象有多层扩展；交互片段在 `app.js` 的同一闭包中展开，单文件语法通过并不足以证明接入正确。
3. 按现有变更提交/回滚机制实现。涉及宿主空洞、分组、整层或 Alt 复制时检查关联对象与选择状态；不要为同一模型的不同视图新增互不一致的存储。
4. 工程结构变化同时检查完整 `StudioModel.validate` 链、旧 JSON 迁移和保存恢复。修改显示或操作限制时同步帮助内容，重建网页与外部说明。

## 验证与交付

依据 [验证规则](../../rules/validation.md) 选择对应回归，网页源码变化先构建再测试。复杂手势或视觉变化增加适当的真实浏览器检查；不为纯文字改动运行整个封装链。

完成后按 [AGENTS.md](../../../AGENTS.md) 向 `logs/CHANGELOG.md` 追加本次实际行为、影响文件和验证结果，说明未验证部分。交付内容应能回答：用户如何触发、现在会发生什么、哪些检查支持这个结论。
