# 透视视图性能分析 · 2026-10-30

## 复现与测量

本次在 Windows、Node.js 24.21.0、Chrome 156.0.8078.74、NVIDIA GeForce RTX 3060（ANGLE / D3D11）、1600 × 1000 浏览器视口下，对修改前后的离线单页运行相同脚本。每组分别测试空选和单选状态下的连续转头；真实鼠标按下/松开建立手势，转头事件按 `requestAnimationFrame` 触发。每个状态采样约 1 秒，同时采集 Chrome CPU profile、帧间隔和 GPU 统计。断言组件始终在视锥内、相机运动期间不重建几何或 GPU 批次。

三种图稿分别为普通平面、55% 不透明度平面、平面/墙壁/楼梯/爬梯/旋转楼梯等量混合。每种包含 400、1200、3000 个组件，保留网格和高度参考线。正式启动种子保持空工程。

这些是同一机器的合成场景实测，接近 60 FPS 的结果受到浏览器刷新频率限制；不能用作其他显卡、超高分屏或所有工程的帧率承诺。

## 实测结果

以下 FPS 均为**选中组件后连续转头**，不含建场和松开后的界面刷新；点击为 Playwright 完成真实画布点击的墙钟耗时，包含浏览器协议开销，不是纯几何求交时间。

| 场景 | 组件数 | 优化前 FPS | 优化后 FPS | 点击耗时：前 → 后 |
| --- | ---: | ---: | ---: | ---: |
| 普通平面 | 400 | 26.2 | 60.3 | 118 → 21 ms |
| 普通平面 | 1200 | 4.1 | 60.6 | 510 → 23 ms |
| 普通平面 | 3000 | 1.4 | 60.7 | 944 → 44 ms |
| 半透明平面 | 400 | 26.4 | 60.3 | 113 → 16 ms |
| 半透明平面 | 1200 | 5.0 | 60.0 | 501 → 21 ms |
| 半透明平面 | 3000 | 1.6 | 55.9 | 978 → 60 ms |
| 五类实体混合 | 400 | 3.2 | 60.2 | 332 → 11 ms |
| 五类实体混合 | 1200 | 调用栈溢出 | 60.5 | 失败 → 31 ms |
| 五类实体混合 | 3000 | 未运行¹ | 59.7 | 未运行 → 70 ms |

¹ 原版在 1200 个混合组件处因 `Math.min(...大数组)` 抛出 `RangeError: Maximum call stack size exceeded`，该轮终止，未继续测试原版 3000 个混合组件。

- 3000 个普通平面的 P95 帧间隔从 750.6 ms 降至 16.8 ms；右键松开后的处理从 1694 ms 降至 53 ms。
- 3000 个半透明平面的绘制调用从 2922 次降至 1 次（该视角下网格在视锥外），P95 帧间隔从 633.8 ms 降至 17.4 ms。
- 3000 个混合组件共 308400 个三角面。另做空选、选中旋转楼梯各 15 秒的持续转头测试，分别约 60.0 / 59.7 FPS，选中时 P95 为 16.8 ms；期间 `geometryBuilds`、`sceneBuilds` 不增长。
- GPU 资源统计在九组场景中均为最多 3 份几何缓冲，组件缓存与当前可见实体数量一致。

## 热点与实现

原版 CPU profile 显示，选中后每帧生成全图 SVG；轮廓生成又为每个组件扫描全部投影面。3000 个普通组件的采样中，该逐组件 `faces.filter` 自身占约 667 ms；空洞筛选约 721 ms，曲面几何包装约 424 ms，`getBoundingClientRect` 约 715 ms。数值为该轮采样的累计自身时间，不能相加解释为单帧耗时。

本次实现：

1. **透视覆盖层按需计算**：每帧计算标注和所选实体/宿主空洞的手柄，导航不生成全图 SVG。创建和路线编辑继续保留所需场景信息，输出仍用完整模型。
2. **点击先筛选候选**：复用 GPU 网格的世界坐标包围盒，对指针射线筛选候选，再沿用原来的投影面、孔洞和标注精确拾取。诊断接口的完整场景保留按需刷新及缓存。
3. **修复几何缓存抖动**：使用按活对象关联的 WeakMap，消除超过 512 件后循环淘汰；冷构建仅采样宿主及其空洞，避免每个组件重复采样全图的曲线。楼层高度、宿主和空洞的物理参数仍参与失效判断。
4. **减少重复扫描与 DOM 重建**：投影面按组件一次分组；组件列表按宿主一次整理空洞，内容未变时只更新选中样式和无障碍状态。
5. **半透明合批**：复用现有 Three.js，把透明度写入 RGBA 顶点属性，按组件深度更新同一份索引缓冲，跨透明度维持原来的由远到近混合顺序。相机平移不重新排序，几何不变时不重建网格。
6. **消除大型数组展开溢出**：高度参考线及内容边界使用逐点累计最值。

没有增加第三方依赖或网络请求；Three.js、字体和资源继续内嵌于离线单页。

## 正确性、证据与复现

- `npm run build`：重建 `dist/index.html`。
- `npm test`：整套应用回归，新增 `verify-geometry-cache.cjs`，比较局部/完整文档几何，包括孔洞、贯穿、内轮廓、弯墙、曲面、集合实体、楼层和原地修改失效；800 个活组件重复遍历保持缓存。
- `node tests/browser-perspective.cjs`：真实透视移动/旋转/尺寸、单次撤销、近裁剪、PNG/SVG 下载及视图切换。
- `node tests/browser-camera-navigation.cjs`：六向移动、键盘/右键组合、焦点与编辑保护。
- `node tests/browser-component-list.cjs`：真实列表选择、排序、取消、宿主空洞、暂存恢复、窄屏与主题。
- `node tests/browser-perspective-caching.cjs`：17 次真实点击与完整场景拾取一致；四个方位、四种透明度与原有逐对象 Three.js 绘制对照。内部颜色差异不超过 2，最坏只有 26 个颜色通道在抗锯齿边缘相差 3–5（0–255）；12 次位置/可见性/透明度重建后 GPU 几何与缓存数量有界。

压力测试入口：

```powershell
$env:STUDIO_PERF_LABEL='local'
node tests/browser-perspective-performance.cjs
```

可选变量：`STUDIO_BROWSER` 指定 Chrome 可执行文件；`STUDIO_PERF_HTML` 指定相对 tests/ 的离线页面；`STUDIO_PERF_COUNTS='400,1200,3000'`；`STUDIO_PERF_KINDS='opaque,transparent,mixed'`；`STUDIO_PERF_MS='15000'`；`STUDIO_PERF_SELECTED_INDEX='4'` 选择旋转楼梯。前后比较时须使用相同参数，分别构建/保存对应页面，不并行运行其他负载测试。

本次本地证据位于 `qa/perspective-performance/`（`before-final.json`、`after-final.json`、两份 `.cpuprofile`、`soak.json` 和截图）、`qa/perspective-caching/`、`qa/perspective/`、`qa/camera-navigation/`、`qa/component-list/`。qa/ 为忽略目录，维护报告及测试脚本纳入源码。

## 已知边界

- 3000 个复杂混合组件的首次同步建场仍约需 5.2 秒。首次完整诊断场景生成约 1.7 秒，后续同状态缓存访问约 4–5 ms；正常画布点击已通过候选筛选避开这条全图路径。导出和适配完整图稿仍需遍历完整几何。
- 本轮压力数据覆盖导航、单选与拾取；未测量数千组件同时选中时的大量选择轮廓、长时间连续几何拖动、数千文字/路线标注或更多图稿同时驻留的内存上限。
- 半透明组件继续采用原有逐组件排序语义，互相穿插的透明面仍有普通透明渲染的排序限制。
- 未重新封装 Windows EXE，也未验证其他显卡、手机或实际 Electron 发行程序。此次交付为源码和重建的离线网页。
