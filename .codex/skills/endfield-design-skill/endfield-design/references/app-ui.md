# APP、桌面工具与游戏向 UI

先从 `surface-families.md` 选择主家族。本文件处理交互界面的通用决策，不提供一套必须照搬的"终末地外壳"。

## 先保护产品逻辑

检查已有框架、导航、token、组件和状态管理。默认保留信息架构、路由、文案意图与组件所有权；用户只要求换视觉时，不重写产品结构。

确定：

- 当前屏幕的唯一主要任务；
- 需要持续可见的状态；
- 可以按需展开的详情；
- 键盘、鼠标、手柄或触屏中的主要输入方式；
- 主家族以及最多一个次家族。

## 空间与层级

- 把最重要的内容当作场景，而不是把所有内容装进相同卡片。地图、人物、物品矩阵、数据行或流程关系应占据主画布。
- 导航、资源、筛选、详情和行动分别停靠到稳定区域。让它们在位置和形状上保持角色一致。
- 斜楔、扇面、径向弧、竖排轨可以承担组织结构（内容沿其轴线排布），前提是它服务当前任务，且交互命中区保持可预测。
- 使用明度、面积、遮挡关系、1px 线和局部实色建立平面深度。阴影不是禁用项，但应有明确的抬升、遮罩或焦点语义。
- 通过不等宽栏、断开的网格和局部密集区形成非对称；不要为了"错落"破坏扫描、对齐和操作距离。

## 系统 chrome 语法（可选件，按需取用）

- **面包屑**：`// 模块 / 子页` 斜杠语法，置于左上；层级深的档案库可用 文件夹 > chip > 标签。
- **区段头**：左侧短竖条（黄或主题色）+ 标签，或深色横带；重要计数可跟在标签后。
- **通知**：橙色菱形/方块角标；未读消息可用黄色角形横幅。
- **倒计时**：胶囊 chip，绿=充裕、红=紧迫。
- **键位提示**：PC 游戏向界面可加白色小方块键帽层；触屏与网页产品不要伪造键帽。
- **系统页脚**：延迟/版本/UID 等真实运行信息可常驻角落小字；没有真实数据就不要放。

## 形状语义

| 语义 | 优先形状 | 可选强调 |
| --- | --- | --- |
| 主行动（工作室/工具面） | 白色胶囊 + 圆形图标章 | 长条内左侧短划线 |
| 次行动 | 深色胶囊或深色小 chip | 图标章 |
| 强调行动对（如 ×1/×10） | 白条 + 黄条并列 | 巨型描边数字 |
| 导航、权限、机械面板 | 直角、切角、斜楔 | 黄/主题色实底、角钩 |
| 技能、头像、仪表、范围 | 圆、环、弧 | 冷却弧、选中环、刻度 |
| 对话、筛选、资源、短状态 | 圆角矩形、胶囊 | 轻底色、状态点 |
| 物品、属性、文档、任务 | 矩形或轻切角面板 | 稀有度边条/底部渐变、标题轨 |
| 地图区域与工业路径 | 自由轮廓、节点和连线 | 局部填充、路径流向 |

同一屏可以混用，但同一语义必须保持一致。不要把 `border-radius` 或 `clip-path` 当作品牌开关。

## 颜色与主题

- 中性底分为亮工作面、混凝土/摄影棚面、烟灰操作面三类；按主内容选择，不必强制"外壳暗、内容浅"。
- 遵循 SKILL.md 的颜色角色表：黄=行动/选中，橙=第二强调（通知、倒计时、等级、数量），荧光黄绿=成长增益，蓝=正向数据/流程，青=地区/机构主题，红=危险紧急，绿=确认，紫=特殊稀有；稀有度色阶 蓝→紫→金→橙。
- 状态色必须同时提供图标、文字或形状区别，不能只依赖颜色。
- 富文本中的机制词可行内着色并配小图标（如 青=法术、绿=自然、橙=灼热），同一产品内语义映射必须唯一。
- 角色、活动和地区主题可以替换或包裹系统色，甚至整页接管（同构换色）。保持一种主主题色、少量语义色和中性层级。
- 为颜色建立命名角色，如 `--action`、`--selected`、`--notify`、`--gain`、`--danger`、`--operator-accent`；不要让组件直接依赖 `--yellow`。

## 排印与图标

- 功能正文优先清晰的 CJK 无衬线；数字界面使用半窄体与 tabular figures。
- 巨型数字、英文索引、幽灵描边字和技术微标只能在确实需要概览、定位或分组时出现。
- UI 图标保持同一视觉家族，但允许填充图标、线性图标和实心几何按层级分工。图纸式"蓝图网格上的图标"适合百科与索引页。
- 禁止 emoji 充当最终产品图标；原型占位时需明确可替换。

## 交互状态

按组件实际能力实现以下状态：

- `default`：主要和次要行动可分辨；
- `hover`：仅用于有指针的环境，不承担唯一信息；
- `focus-visible`：高对比轮廓，不能被切角或 `overflow` 裁掉；
- `active/selected`：角括号、边条、白色反转、选中环或位置变化至少一种明确表达；
- `disabled`：降低强调但保持可读，说明不可用原因时提供文本；
- `loading`：保持布局稳定，避免伪造完成数据；
- `empty`：解释为什么为空以及下一步；未获得的收藏项可用准星占位符；
- `error/success`：语义色之外还需图标或文字；
- `completed`：可用明暗反转庆祝（深底 + 黄色区 + 描边大词 + 领取章），同列表中未完成项相应降为浅灰。

状态形状服从组件：地图可以发光描边，页签可以底条或黑白反转，头像可以选中环，列表行可以侧脊或白色渐变。不要把黄色切角签当作所有选中态。

## 家族适配

- **HUD/枢纽**：中心留给场景；键位提示独立成层；控件尺寸和输入设备有关。
- **地图**：选区和路线优先，详情跟随当前区域；地区主题可整页接管。
- **角色工作室**：主体优先，属性侧停靠；进阶页可用斜楔/扇面组织。
- **仓库矩阵**：扫描效率、筛选和比较优先；稀有度与徽章体系语义化。
- **技能树/工业流程**：真实连接关系优先于装饰线。
- **数据简报**：深色数据行带 + 行内图表 + 语义数字色；异常优先可见。
- **通讯/Wiki**：阅读舒适度优先，允许圆角气泡和更常规的文档组件。

## 响应式与可用性

- 窄屏不是简单把桌面三栏堆成一列。决定哪些内容成为抽屉、底部面板、分页或横向切换。
- 触屏目标按目标平台保证足够面积；锐角背景不应缩小真实命中区。
- 长名称、中文换行、动态数值和缺图必须在布局中测试。
- 不因风格隐藏滚动条、焦点、表单标签或错误说明。

## 验收

1. 五秒内能否看出主要任务和当前选择？
2. 去掉黄色后，结构和交互是否仍成立？
3. 形状是否表达语义，而不是所有组件共享一个外形？
4. 是否能指出主家族，且没有退回固定品牌页眉、查询带或平均卡片网格？
5. 颜色是否遵守角色表（橙=系统强调、红=危险等），没有互相冲突？
6. 键盘、触屏、长文案、加载和错误状态是否仍可用？
