# 响应式网站与落地页

终末地官网可用于研究品牌叙事、媒体展示和章节切换，但不是一套可以直接复制的 section 模板。网站先服务内容、访问者和转化，再使用终末地视觉语言建立气质。

## 设计前检查

- 阅读现有页面结构、路由、字体、token、组件库和动效依赖。
- 明确访问者、主要行动、真实素材数量和内容更新方式。
- 从 `surface-families.md` 选择主家族：多数官网使用“官网与产品落地页”，但活动入口可局部使用 KV，资料区可使用编辑物料或 Wiki 家族。
- 缺少真实图片时，优先选择排印、CSS 图形、地图/流程等可诚实完成的结构，不伪装库存照片为最终素材。

## 宏观结构

从内容选择结构，不使用固定的 hero → 三卡 → CTA → footer：

- **场景主导**：全幅地点/角色，导航和章节停靠在边缘；适合世界观和版本入口。
- **编辑分栏**：不等宽文字、媒体与索引穿插；适合新闻、档案和内容品牌。
- **档案索引**：筛选、编号、列表和详情组成浏览系统；适合干员、资料与公告。
- **时间/路径结构**：内容沿时间轴、工业线路或地图节点展开；适合版本和玩法说明。
- **产品工作台**：交互演示或数据视图成为 hero；适合工具和社区产品。

一个页面可以变换区块节奏，但每次变换都要由内容类型或叙事阶段解释。明暗交替、黄色横带和括号标题都是可选分节手段，不是固定顺序。

官网已确认的分节语法（可选件，不是必选清单）：

- 巨型 `//` 跑马幽灵字作区块分隔；
- 章节头用黄色横带（可配等距线稿插图）或竖排侧签；
- 区块标签 chip + 多色注册微条 + 微文字组合；
- 媒体轮播配黑底分页器（`‹ n/N ›` + 黄色下划刻度）或圆形前后钮；
- 墨迹黑烟 + 撕裂纹理刊头，或由版本彩色场景接管的首屏；两者随主题选择；
- 左缘竖排图标导航轨；底部黑色下载/行动带。

同一页面最多选两三种，且要与内容气质匹配；信息工具类站点通常一种都不需要。

## 页面层级

- 导航要反映真实信息架构。Logo 块、汉堡、浮动胶囊或侧轨均可，按链接数量和滚动行为选择。
- 每个主要区块需要不同于正文的入口信号，但不要求重复同一个中英标题组件。
- CTA 的形状、颜色和位置要与主要行动一致。角形按钮适合强行动；胶囊适合紧凑工具栏；文字链接适合编辑内容。
- 多媒体控件必须清楚、可键盘操作，并提供可访问名称。

## 视觉语言

- 使用纸白、混凝土灰、烟灰或近黑建立可读的信息平面；版本画面可大面积接管首屏。官网可见白色外壳、墨黑排印与系统黄导航，也可见青紫主题的完整雪域画面，不能把旧版本墨迹背景固化为全站规则。
- 通过偏心构图、边缘停靠、截断的大图/大字和不等宽网格体现空间张力。
- 英文微标、编号、坐标、网格、等高线和裁切标只在帮助定位、分组或建立叙事层时使用。
- 角色或活动页面可以采用独立主题色、展示字体和纹理系统；不必保持整站只有黄色。

## 交互与动效

- 动效用于解释状态、空间和层级：区块擦入、地图位移、标签切换、路径推进、媒体转场。
- 小交互通常保持快速克制；大型章节转场可以更慢，但必须允许跳过或不阻挡内容。
- Hover 不能是唯一状态；同时实现 `:focus-visible` 和触屏选中反馈。
- 支持 `prefers-reduced-motion`，降级后仍保留内容和状态。
- 不默认使用弹跳、持续漂浮、全页平滑滚动或每张卡片的放大阴影。

## 响应式

- 至少检查 320、375/390、768 和桌面宽度；检查横向溢出、长标题和真实中文文案。
- 手机端重新安排阅读顺序。侧轨可以变成顶部索引、抽屉或底部工具，不必保留桌面几何形状。
- 使用 `minmax(0, 1fr)`、`min-width: 0` 和内容驱动断点保护不可控内容。
- 大标题用 `clamp()`，但要同时设置合理行长与断词策略。
- 装饰出血使用独立的无交互层和局部裁切，不能用全局 `overflow-x: hidden` 掩盖布局错误。
- 官网实测（2026-09-05）：宽屏保留左缘竖排图标轨与底部横向下载带，窄屏改为白色顶栏 + 汉堡与竖排下载卡组；同一分节在两种宽度下媒体与说明的顺序可以不同。具体观察见 `evidence-map.md › H`。

## 可访问性与内容真实性

- 保持语义标题层级、可见焦点、足够对比度和可理解的链接文字。
- 不编造用户数、增长率、奖项、媒体评价、合作方和倒计时。
- 技术微标如果只是氛围，应从辅助技术隐藏；如果承载含义，则必须可读且翻译准确。
- 官方名称、标志、角色图与截图只有在用户选择并有权使用时才进入成品。

## 验收

1. 页面结构是否由内容决定，而不是官网或旧模板复刻？
2. 相邻区块是否有节奏变化，同时仍属于同一系统？
3. 去除装饰纹理后，层级和主要行动是否清楚？
4. 手机端是否重新编排，而不只是缩小桌面？
5. 动效、键盘焦点、真实文案和缺图状态是否通过？
