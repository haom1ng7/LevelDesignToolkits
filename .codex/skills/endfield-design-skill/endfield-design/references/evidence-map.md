# 官方参考证据图谱：观察 → 规则

本文件记录从官方素材中提炼出的**文字观察**，以及每条观察支持了哪些规则。来源元数据（类别、可用性、日期、置信度）在 `source-registry.md`，以 `EV-*` 编号互相引用。本文件用于维护和 Study 任务，不是普通生成任务的必读文件；Skill 的运行不依赖任何此处提到的图片或网页。

## 证据使用原则

- 只有跨多个独立界面、主题或媒介反复出现的特征才能进入核心 DNA；单张画面无论是否公开，只能进入家族、条件或主题层。
- 单个界面的结构进入对应家族，不提升为全局规则。
- 单个活动、角色或地区的颜色、字体和图形进入主题专用层。
- 公开网页（`EV-WEB-*`）适合验证品牌叙事和 Web 行为；游戏截图（`EV-UI-*`）验证组件、形状和交互语义；运营物料（`EV-ED-*`）验证主题变化和编辑结构。
- 仅由 `private-game-capture` 支持的结论，公开读者应视为维护者观察而非可直接复核的事实。
- 账号身份与采样入口见 `official-sources.md`。同一活动的转载、长图裁片与跨账号重复物料按同组证据处理；静态画面中的控件外观不证明交互行为。

### A. 运行 HUD 与径向枢纽（EV-UI-01、02）

- HUD：中心留空、四角成组；圆形技能环带冷却弧；键位提示小方块遍布；黄色点状导航路径带文字；血条青色。

### B. 地图与区域导航（EV-UI-03、04、05）

## 已否决的假设

- 全系统零 `border-radius`；
- 黄色是唯一强调色；
- 展示物料禁止高对比、装饰或刷写字体；
- 所有长图固定"品牌行 → 大标题 → 色条 → 卡片 → 墨底页脚"；
- 存在可全局复用的查询/报表组件骨架；
- 主题变化只需替换黄色 token；
- 微缩模型、AR 测绘层或右置标题是所有 KV 的固定结构；
- 数据仪表盘没有官方参照（EV-UI-17 即范式）。
- “正向数据色是青”——产耗行与低稀有度实测为蓝（#2a84b4 / #24bafc），青只作地区/机构主题色。
- “版本日历固定红黑白，红是其结构常量”——冰蓝新版保留时间结构（EV-WEB-06）。
- “官网首页必须用墨迹黑烟”——版本画面可以完整接管（EV-WEB-05）。
- “所有编辑价格与日期都必须使用 UI 的橙/黄”——主题可以接管排印强调，不能反向改写系统语义（EV-WEB-06；EV-ED-16）。

## 更新规则（Study 的写入边界）

- Study 默认只输出观察报告：区分反复出现的特征、主题专属特征、与现有规则冲突的证据，并给出置信度。
- 只有用户明确要求"保存 / 更新 / 锁定"时，才修改本文件、`source-registry.md` 或任何规则文件；修改前先说明将改动哪些文件、哪些章节。
- 新增全局规则需至少两个独立界面、主题或媒介交叉支持，或明确的官方设计规范（或本身包含多个独立表面的官方资料）；单张官方画面无论是否公开，只能进入家族、条件或主题层。
- 同一会话内已明确给出的探索与更新授权，在其声明范围内持续有效：先核对范围，不因进入另一官方账号或处理下一张图重复请求；范围外、换会话或改动 SKILL 核心 DNA / 颜色角色表时重新确认。
- 不因一张新图增加新的全局禁令；不登记本地路径、哈希或文件名。

## Study 操作流程（用户授权保存后）

按顺序执行；每一步的产物是下一步的输入。

**未授权阶段（默认，不写任何文件）**

1. **写观察**：对用户提供的素材，或按 `official-sources.md` 从获授权渠道采样的内容，实际查看后把可复述特征写成文字，逐条与本文件的核心 DNA、颜色角色、家族观察、条件母题、已否决假设比对，标为三类之一：
   - **重复出现**：已有观察再次得到支持；
   - **新的家族/主题/条件特征**：只有这张图支持；
   - **与现有规则冲突**：标明冲突的规则位置与相关证据编号。
2. **判断层级**：新特征要进入 SKILL 全局规则，需至少两个独立来源交叉支持（不同界面、主题或媒介），或来自本身包含多个表面的官方规范。不满足则停在家族/条件/主题层。
3. **输出报告**：列出三类观察、各自拟进入的层级与文件章节、置信度，以及若保存将改动的文件清单。到此为止；用户未说"保存 / 更新 / 锁定"就不进入下一阶段。

**授权阶段（用户明确要求保存后）**

4. **登记来源**：在 `source-registry.md` 对应分区新增一行 `EV-*`（类别、可用性、观察日期、置信度），派生规则列先留空。ID 取该分区当前最大编号 +1，不复用已删除的编号。
5. **写入观察**：重复出现 → 在本文件对应行追加来源编号，必要时把置信度从 `medium` 提到 `high`；新特征 → 写入对应家族小节或条件母题，不动 SKILL 的全局规则；冲突 → 用户已授权依据新证据更新时，可将旧概括收窄到实际适用的版本或体裁，保留旧证据并解释修正。无法由证据解决、涉及用户已确定的产品语义与项目例外、或需要改动 SKILL 核心 DNA 与颜色角色表时，先记录差异，再请求裁决；收窄写入"已否决的假设"并保留旧证据编号。
6. **同步规则文件**：按“观察进入的规则”列逐个改动，同步顺序固定为 SKILL → surface-families / 各家族参考 → techniques 的 token 与示例 → official-motifs。颜色角色只改 SKILL 的权威表，其他文件只改引用与注释，不再各写一份定义。
7. **回填派生规则**：回到 `source-registry.md` 填写该条目的派生规则列（“文件 › 章节”），并检查本文件里所有引用该编号的行。
8. **验收**：
   - 本文件引用的每个 `EV-*` 都在登记表中定义；登记表中派生规则列非“未单独派生规则”的条目，至少被本文件引用一次（`EV-UI-06~11`、`EV-UI-01、03` 这类范围与并列写法算引用）；无重复 ID；
   - SKILL 颜色角色表与 techniques 的 token 注释、README 的一行摘要三处一致；
   - 被改动的家族小节能用一句话说出新观察支持了哪条规则；
   - 若改了 SKILL 的门或全局规则，用一个已有样例（`docs/samples/`）重跑八道门，确认不因新规则误判。
9. **报告**：列出改动的文件与章节、新增/提升/否决的观察各几条、以及本次仍未裁决的冲突。
