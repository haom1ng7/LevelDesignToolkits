## 从渠道到可用观察

1. **按体裁采样**：选择与任务相关、信息完整的代表作。优先补未覆盖的内容结构；研究系列稳定性时再看另一期或另一主题，不以浏览帖子数量替代分析。
2. **核对出处**：回到原帖确认作者、标题、链接与可见发布日期。分开记录观察日期；不把图片上传路径中的日期当作发布日期。相对时间不确定时保留原显示或留空。
3. **隔离证据**：社区外壳、官方正文、引用内容与评论区分别处理。只把属于目标正文的图文登记为该作者物料；评论配图、站点按钮和用户头像不能混入视觉样本。
4. **看清再判断**：网页要实际打开并检查可见状态；长图同时检查全局阅读节奏与局部字号/排版。超长图可分段查看，动图可抽帧核对局部变化；抽帧不能证明播放节奏或真实交互。
5. **划分层次**：分别描述媒介结构、主题色/字形、内容图像、系统状态。场景里的环境光、商品包装的黄黑色和外层海报主题不能混作一条 UI 颜色规则。
6. **避免重复计票**：同一版本 KV、转载图或一张长图的多个裁片按一个来源组处理。多账号发布同一活动不自动增加独立性；升为全局规则仍需跨界面、主题或媒介支持。
7. **登记与更新**：使用 `source-registry.md` 和 `evidence-map.md` 的流程。明确授权探索并更新后，完成采样、说明改动范围、写入与验收；不因每换一个账号就重复索取授权。

## 验证与保存

- 分别报告视觉、响应式、交互状态；区分实际网页、官网静态资产、官方发布的游戏截图与亲自操作的游戏界面。看到截图不等于体验了游戏。
- 记录实际生效的视口，而非只记录设置请求。未加载、隐藏或无法点击的区块写明限制；从页面取得的图片可以验证静态设计，不能补足该区块的互动验证。
- 公开 Skill 保存文字观察、来源链接和派生关系；原图、本地文件名、哈希与分析裁片保存在维护者私有资料区，不随 Skill 打包。
- 源站改版时保留旧观察的版本与日期，新增当前观察；不要把历史布局当成当前网页的验证结果。
