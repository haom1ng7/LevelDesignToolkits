# 构建关卡设计工具箱离线产物

按用户需要生成网页、教程或本地发布附件。先读 [发布规则](../../rules/release.md)，只执行与所需交付物相关的步骤。

## 检查输入

检查 `package.json` 的实际脚本、锁文件与运行时。核对帮助媒体、源码归档路径和许可证，不把历史检查记录当作当前缺件已经解决的证据。

源码归档清单见 `tools/release_files.py`，日志是 `logs/CHANGELOG.md`；源码包还包含 hooks 测试所需的脚本。遇到缺件时先定位用途，在打包任务范围内补齐必需资源或修正过时清单，不用空文件假装完整。

## 按交付物构建

| 交付物 | 命令及主要输出 |
| --- | --- |
| 离线网页 | `npm run build` → `dist/index.html` |
| 同步教程 | `npm run manual` → `docs/使用说明.md`、`docs/使用说明.html`；内置内容变化时也重建网页 |
| 网页附件和校验值 | `python -X utf8 tools/package-release.py` → `release/`，需要先构建网页与教程 |
| 源码上传目录 | `python -X utf8 tools/prepare-github.py` → 新的 `release-upload/`，脚本不覆盖已有仓库目录 |

系统 `python` 不可用时使用实际可用的 Python 3 路径，不为此改写用户全局配置。首次安装依赖可能需要网络，按当前环境的权限流程执行。

## 检查与交付

依据 [验证规则](../../rules/validation.md) 检查空种子、离线帮助和实际导出；确认网页和源码归档包含必要资源与许可。若交付开发配置，检查 `.codex/`、`AGENTS.md` 和其测试的引用配套，不能把本机路径直接当作跨机器配置。

报告真实生成的路径和检查结果。构建本地附件不代表远端上传或站点部署；外部发布只有在用户请求相应动作时执行。修改构建、清单或教程行为后按 [AGENTS.md](../../../AGENTS.md) 追加日志。
