# 验证关卡设计工具箱

以改动范围或用户提供的复现步骤为输入，输出本次实际执行的检查、失败原因与尚未覆盖的行为。命令在项目根目录运行。

## 选择检查

先读 [验证规则及测试映射](../../rules/validation.md)。检查依赖和构建产物的新旧：多数 `verify-*.cjs` 加载 `dist/index.html`，应在相关源码修改后重新构建。

- 局部功能选择映射中的对应回归；共享模型、渲染或拼装变化运行 `npm test`。
- hooks、规则和 skills 的集成变化运行 `node --test tests/changelog-hooks.test.cjs`；它不需要 jsdom 等 npm 依赖。
- 输入、鼠标命中、拖动或视觉问题，用真实浏览器复现。现有 `browser-*.js` 是操作片段，应检查 `page` 驱动、页面地址和历史输出路径后使用。
- 导出问题先明确图稿类型、三视图模式、完整图稿/当前视野与 PNG/SVG，再检查实际下载文件。文件检查脚本需要本次对应的报告及产物。
- 桌面问题读取 [发布规则](../../rules/release.md)，用独立配置和真实目标 EXE 验证，区分目录版和单文件启动器。

## 解释结果

失败时先区分环境缺件、旧构建产物、测试驱动/路径问题和应用行为错误。不要通过跳过断言或引用历史结果把失败写成通过；发现问题后只修复当前授权范围内的内容。

分别报告自动回归、真实操作和实际文件检查，保留复现所需的图稿/视图/动作信息。只运行验证而未改功能时无需新增日志；若修复了功能或开发流程，按 [AGENTS.md](../../../AGENTS.md) 更新 `logs/CHANGELOG.md`。
