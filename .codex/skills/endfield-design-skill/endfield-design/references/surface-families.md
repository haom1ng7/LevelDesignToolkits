# 界面与物料家族

先按内容和交互任务选择家族，再决定颜色、切角、纹理等表面母题。家族不是模板：其中的结构提示用于建立层级，不要求复制固定布局。带 ◇ 的条目是官方参考中确认的可选结构件，按需取用。

## 选择方法

优先问四件事：

1. 用户是在行动、查找、比较、阅读，还是被一张视觉吸引？
2. 主角是空间、人物、物品矩阵、流程关系、对话、数据，还是叙事内容？
3. 信息需要持续操作，还是一次性阅读？
4. 主题来自系统功能，还是某个角色、地区或活动？

每个屏幕选择一个主家族。组合时让次家族只影响局部组件，例如"暗色地图外壳 + 浅色任务详情"，不要把两个完整模板叠在一起。

## A. 运行 HUD 与系统枢纽

适合实时状态、战斗、导航与高频行动；也覆盖"径向主菜单"这类系统入口。

- **视觉锚**：场景本身；枢纽形态下是中央地图/主体，功能磁贴沿弧线或边缘排布。
- **结构**：中心保持可视；生命、技能、任务、交互分别成组。◇ 键位提示小方块是 PC 端的独立输入提示层；◇ 导航路径可以是发光点线带。
- **形状**：圆形技能/交互（含冷却弧）、短角钩、细状态条、少量斜翼行动块可以并存。
- **颜色**：中性白图标为基础；黄用于目标或选中，红/绿/青保留状态语义（血条可为青色）。
- **避免**：把所有控件做成同尺寸黑黄磁贴；用装饰线遮挡场景；为"科幻感"添加无意义读数。

## B. 地图与区域导航

适合空间探索、区域状态、路线、任务点和工业网络。

- **视觉锚**：地图区域、路线或当前选区。
- **结构**：全幅地形/拓扑画布 + 边缘区域导航 + 与选区绑定的详情轨。◇ 未探索区可用斜纹填充；◇ 选区高亮可加光柱等空间性强调。
- **形状**：等高线、轮廓填充、范围圆、节点、路径和角钩框；详情卡形状服从信息密度。
- **颜色**：未选区域保持灰阶；高亮色集中在当前路径、选区或任务。◇ 地区可拥有整套主题色（例：一个地区青蓝、另一个青柠），同构换色接管该地区的全部管理页面。
- **避免**：普通仪表盘网格；所有区域同时高亮；装饰性地图标记与真实任务点混淆。

## C. 角色与装备工作室

适合干员、武器、装备、属性和养成。

- **视觉锚**：人物、装备模型或关键等级数字。
- **结构**：主体占据最大空间，属性与导航在侧边停靠。◇ 巨型斜楔或扇面可以作为进阶/养成内容的组织结构——数据条与节点沿斜轴排布；◇ 摄影棚地面可带站位刻度圈与幽灵大数字；◇ 收藏/潜能类页面可用实体道具拼贴（打印品、证卡、徽章）作画布。
- **形状**：角色/技能头像可圆；属性板、标签和行动区可使用直角、斜楔或条带。◇ 主行动=白色胶囊+圆形图标章，次行动=深色胶囊。
- **颜色**：系统黄可标记当前选择；角色主题色可以接管局部背景、稀有度和装饰；技能与增益文本用行内语义着色（青=法术、绿=自然、黄=数值等，随项目语义表）。
- **避免**：每项属性一张独立卡；角色被 UI 切碎；把巨型黄色斜楔当作每个详情页的必选项。

## D. 仓库、商城与矩阵浏览

适合大量物品、分类、筛选、比较和获取路径。

- **视觉锚**：当前物品或当前分类；矩阵本身是工作区。
- **结构**：稳定的密集网格 + 清晰筛选/资源条 + 局部详情。◇ 商城可用"实体商品摄影"卡；◇ 制造/工坊页可用中央圆形展台放大当前物品。
- **形状**：物品槽以矩形为主；资源、数量、筛选可用胶囊或短标签。◇ 选中=角括号或白描边；◇ 未获得：图鉴格=准星占位符，列表卡=左下锁图标（卡面不变灰）。
- **颜色**：稀有度用底部渐变或底边条，遵循 蓝→紫→金→橙 色阶（最高档可在渐变上叠细斜纹）；徽章叠层各司其职（绿=充裕倒计时、红=紧迫、橙=折扣/超值、深色=限购、压黑=售罄）。当前选择仍需唯一清晰。
- **避免**：为了风格破坏扫描效率；每张物品卡重复大型装饰；把稀有度色当纯装饰。

## E. 技能树与工业流程

适合科技树、生产关系、设施链路、步骤和依赖。

- **视觉锚**：路径、当前节点或阶段门槛。
- **结构**：让连线与依赖关系支配版式，侧栏只承载解释和操作。◇ 浅纸底 + 黄色图标板节点 + 直角折线是官方科技树的基本组合；◇ 阶段可用幽灵大数字分区；◇ 类目列用细竖线分隔。
- **形状**：节点可方可圆，取决于类别；连接线、分支、锁定态和完成态必须优先可读（完成可用黑圆勾章）。
- **颜色**：高亮色沿可达路径流动；锁定、完成、缺少资源需有独立语义。
- **避免**：把流程塞进普通卡片列表；装饰线与真实连接线使用同一种视觉强度。

## F. 数据简报与监控

适合产耗统计、排行、监控列表、运营周报等以数字为主体的界面或物料。

- **视觉锚**：主结论或异常项，不是图表装饰。
- **结构**：官方范式是浅色画布 + 深色数据行带，每行内嵌该项的小型图表（面积图/走势），行左收藏与名称，行右当前值与理论值分列。◇ 列头做成灰色胶囊带并用竖线分隔；◇ 表格页变体：白色分组头卡 + 深色数据行 + 状态⚠文字 + 行尾白胶囊行动。
- **形状**：行带直角为主；收藏=黄圆星；类目可用左缘色条。
- **颜色**：数字语义色固定——蓝=产出/正向的量值图表，黄=消耗/关注与进度/完成度条，红=超支/异常；不要让主题装饰色与数据语义色互撞。
- **避免**：套用通用 admin dashboard 模板；把每个指标装进等大卡片；用彩虹图例代替语义色。

## G. 通讯、Wiki 与信息工具

适合对话、百科、日志、邮件、任务说明和帮助系统。

- **视觉锚**：当前人物、主题或文档标题。
- **结构**：清晰阅读列 + 列表/索引。◇ 未读可用黄色角形横幅；◇ 百科索引可用"蓝图网格上的图纸式图标 + 幽灵编号"，选中项展开成全高标本竖带；◇ 任务列表用优先级图标语义（黄!!!紧要 / 白!次要）+ 左缘类型色条。
- **形状**：对话气泡、筛选器和状态适合圆角（角色深灰、本人白色）；目录、文档区和系统标签可以更硬朗。
- **颜色**：角色或频道可使用局部识别色；正文关键词可用黄色强调；选中行可做白色反转。
- **避免**：因"终末地风格"牺牲正文行长、对比度和阅读节奏；强行切角每个段落。

## H. 官网与产品落地页

适合品牌叙事、版本内容、功能介绍与转化。

- **视觉锚**：当前章节的角色、地点、产品画面或核心主张。
- **结构**：根据内容选择全幅场景、编辑型分栏、档案索引、时间轴或功能演示。◇ 官方语法包括：巨型 // 跑马幽灵字作区块分隔、黄色横带或竖排侧签作章节头、小标签 chip + 多色注册微条、黑底分页器（‹ n/N ›+黄色刻度）、圆形前后翻页钮、墨迹刊头。
- **形状**：导航、章节索引、媒体控件和 CTA 各自选择语义形状；左缘竖排图标轨是可选导航形态（官网宽屏保留，窄屏收为顶栏 + 汉堡）。
- **颜色**：白色外壳、墨黑文字与系统黄是已见的公共语法；版本首屏可由完整彩色场景接管，例如「雪凇幽梦」的青紫雪域。墨迹黑烟属于特定版本表达，不是首页必需背景。
- **避免**：默认 hero → 三卡 → CTA → footer；每个区块重复相同标题组件。

## I. 活动 KV 与主视觉

适合活动入口、横幅、章节预告和主要宣传视觉。

- **视觉锚**：人物、工业设施、微缩景观或具有叙事性的物件。
- **图像策略四选一**：微缩模型场景（玩法/工业向）；照片拼贴（拍立得+胶带+故障，角色叙事向）；扁平宣传画（巨型图形符号+有限色板+速度几何，竞技/运动向）；整幅绘画（世界观/版本向，可配符文化装饰字题字系统）。
- **结构**：主体与标题形成不对称拉力，为活动名称、日期和行动信息留出真实空间。◇ 类型标签用括号语法 [ 挑战活动 ]；◇ 日期 chip 可用深色块+红角标。
- **颜色**：活动主题色可主导画面（含红青故障双色等高能组合），系统黄只在需要品牌连续性时保留。
- **避免**：自动添加微缩景观、AR 线框和右置标题；每个活动使用同一构图换色。

场景预览是图像优先的邻近用法：环境光、前中后景与真实地点本身即可承担叙事。Delta「雪松林」组图只有少量边角署名，无额外 HUD 或测绘叠层；按场景内容选择表达，不自动套入图解版式。

## J. 编辑型运营物料

适合角色档案、版本日历、活动总结、攻略长图和工业说明。先选叙事体裁，再定版式；同一系列刊物应维持自己的刊头系统。

已确认的官方体裁（结构互不相同）：

- **版本日历**：主题刊头 + 左侧类目竖轨 + 日期锚 + 横幅条甘特节奏，每条活动保留自身主题色；红黑墨刷与冰蓝渐变均有实例（冰蓝来自雪山地区主题），稳定的是时间结构，颜色随版本主地区或题材走。
- **档案/威胁档案**：竖排大字标题 + 档案道具（印章、胶带、纸质文件）+ 层级竖轨（可用中文数字）+ 标本卡矩阵 + 警示红带。
- **人物备忘**：主题色接管 + 身份表格 chip + `//` 章节标题 + 访谈问答带 + 留言板卡片 + 手写批注与贴纸。
- **系统说明书**：编号章节带 + 截图/图解证据 + 红笔批注 + 荧光笔划重点。
- **前瞻卷轴**：全幅截图/画面堆叠，章节标题带 ‹‹ ›› 极简 chrome；适合故事与玩法预告。
- **更新日志**：NEW 章节 chip + 物品卡行 + 证据截图；系统优化篇用"类目色签 + 截图上数字圈标注 + 说明条"。
- **期刊系列**：吉祥物主持 + 固定刊头与 VOL 编号 + 地点标签截图卡 + 清单行带 + 旁批。
- **官方通告**：标签行（深色 chip + 值）+ 大号日期 + Q&A（Q 方块）+ 荧光笔重点 + 价格/规则卡。
- **参与招募**：主题横幅或活泼群像 + 日期/资格/步骤 + 奖励展示；正文规则、示意图与奖励图可以分开发布。
- **商品目录**：系列入口 + 商品名/价格配对 + 单件大图、局部细节与套装说明 + 实物摄影；外层系列主题与产品包装分别处理。
- **主持问答/幕后讲解**：栏目刊头 + 主持问题 + 嘉宾或岗位答复 + 关联图示；人物采访可用成组对话框，技术答复使用连续阅读列。
- **连载漫画**：系列封面与话数 + 按情节分配的分镜/对白 + 低干扰页码；当期画风与封面语法保留在系列层。
- **通用零件** ◇：签到=01–07 日签卡行；通行证=梯度奖励卡行；START/END 起讫标记；继承/流程关系用 » 箭头链。

- **排印**：功能文字保持清晰；展示标题可按人物、地区或活动采用不同字形性格（含毛笔、手写、符文装饰行）。
- **颜色**：允许内容主题色和多个语义色，但需建立主次；技术微标只是辅助层。
- **避免**：固定三段页眉、固定墨底页脚、固定四色注册条；把每份内容都排成数据报告；把某一体裁的道具（如红笔批注）机械搬进不相配的体裁。

## 组合记录

开始制作前留一句短记录：

`动词：Build · 家族：数据简报 · 锚点：超支异常 · 主题：系统黄 + 语义色 · 次家族：无`。

这句话应能解释布局决定；如果它只能描述颜色和装饰，说明还没有选对家族。
